\chapter{Register Map of the Control Interface}\label{app:registers}

The control plane talks to \code{ise\_top} through an AXI4-Lite slave
(\code{regs\_axil}) with 32-bit registers. This map is a starting point: adjust
the formats to your \code{spec-v1}, but keep the \emph{semantics}. In particular,
no parameter the datapath reads may change in the middle of a frame.

\section*{Commit semantics}

On a write of 1 to \reg{LUT\_COMMIT}, the hardware sets
\code{STATUS.COMMIT\_PENDING}. At the next frame boundary it atomically:
\begin{enumerate}
  \item swaps the active and shadow gain-table banks;
  \item copies the shadow \reg{OUTPUT\_GAIN} and \reg{TILT\_RATIO} into the
        active registers the datapath reads;
  \item clears \code{COMMIT\_PENDING} and sets \code{COMMIT\_DONE}.
\end{enumerate}
After a swap, the shadow bank holds the \emph{previous} table. The control plane
must therefore write a complete table before every commit. It must never assume
the shadow bank already contains the current one.

\section*{Applying an intent update}

\begin{enumerate}
  \item The control plane classifies the complaint and computes the new
        parameters: $\beta$, floor, $g_\text{out}$ and tilt.
  \item It computes the 256-entry table with \code{make\_gain\_lut(beta,
        floor)} (\cref{ch:codesign}) and $r=10^{\text{tilt}/(20(K-1))}$.
  \item It waits until \code{STATUS.COMMIT\_PENDING} is 0.
  \item It writes \reg{LUT\_ADDR} = \code{0x80000000} (address 0,
        auto-increment), then 256 writes to \reg{LUT\_WDATA}.
  \item It writes \reg{OUTPUT\_GAIN} and \reg{TILT\_RATIO}.
  \item It writes 1 to \reg{LUT\_COMMIT}, then polls for
        \code{STATUS.COMMIT\_DONE} and clears it by writing 1.
\end{enumerate}

\begin{lstlisting}[style=py,caption={A sketch of the Python driver on the PYNQ (check the MMIO API of your PYNQ version).}]
from pynq import MMIO
from golden.gainlut import make_gain_lut   # same code as the golden model

CTRL, STATUS, OUTPUT_GAIN, TILT_RATIO = 0x00, 0x04, 0x10, 0x14
LUT_ADDR, LUT_WDATA, LUT_COMMIT = 0x20, 0x24, 0x28
PENDING, DONE = 1 << 2, 1 << 3

class EnhancerRegs:
    def __init__(self, base_addr):
        self.mmio = MMIO(base_addr, 0x100)

    def apply(self, beta, floor, g_out, tilt_db, n_bins):
        while self.mmio.read(STATUS) & PENDING:
            pass
        self.mmio.write(LUT_ADDR, 0x80000000)              # address 0, auto-increment
        for word in make_gain_lut(beta, floor):
            self.mmio.write(LUT_WDATA, int(word))
        r = 10 ** (tilt_db / (20 * (n_bins - 1)))
        self.mmio.write(OUTPUT_GAIN, round(g_out * (1 << 13)))
        self.mmio.write(TILT_RATIO, round(r * (1 << 23)))
        self.mmio.write(LUT_COMMIT, 1)
        while not self.mmio.read(STATUS) & DONE:
            pass
        self.mmio.write(STATUS, DONE)                      # W1C
\end{lstlisting}

\begin{tipbox}[Why \texttt{TILT\_RATIO} needs many bits]
With $\pm\qty{12}{\dB}$ of tilt spread over about 1024 bins, $r$ lies within
about $\pm0.14\%$ of 1, and it is raised to powers up to $K-1$. Its rounding
error compounds over the bins. That is why this map gives it 23 fractional bits.
If you chose a smaller frame configuration, or a log-domain tilt, recompute the
error at the last bin and resize the register.
\end{tipbox}
